# QQ 消息增强

AstrBot 插件，只作用于 aiocqhttp（OneBot v11）平台。原名「QQ 小黄脸行内转换」（`astrbot_plugin_qq_face_inline`）。

## 收到的消息

| 情况 | 模型看到的 |
| --- | --- |
| 语音，并且 AstrBot 的语音识别转写成功了 | `[语音] 转写出的文字` |
| 合并转发 | `[合并转发]`，然后每条一行「昵称: 内容」，最后 `[合并转发结束]` |

- **语音**：AstrBot 转写后会把语音换成普通文字，模型分不出这是语音。插件从 QQ 的原始消息里认出语音，在转写文字前加上 `[语音] `。转写失败时不改动。
- **合并转发**：AstrBot 只收到合并转发的 ID，看不到内容。插件通过 OneBot 的 `get_forward_msg` 取回内容（需要协议端支持，SnowLuma、NapCat 都支持），展开成文字：
  - 图片、表情、视频这类内容换成 `[图片]` 之类的占位。
  - 套娃的转发最多展开两层。
  - 总长超过 3000 字就截断。
  - 取不到时写 `（内容获取失败）`。
- 这一步排在天使之心（AngelHeart）之前，所以它记下的聊天记录也是处理后的内容。self-learning 收集消息比它早，学习用的还是原始消息。

## 模型的回复

| 模型写 | 发出去 |
| --- | --- |
| `在呢/汪汪` | 「在呢」+ 汪汪小黄脸 |
| `[@123456] 你看看` | @ QQ 号 123456 +「你看看」 |
| `笑死/笑哭[分段]你也太离谱了` | 两条消息：「笑死」+ 笑哭小黄脸，停顿一下，再发「你也太离谱了」 |

**小黄脸**的规则沿用 MaiBot SnowLuma 适配器：

- 表情前面紧挨英文字母、数字、`_`、`/`、`:` 时不转换（如 `666/赞`、网址）。
- 表情后面紧跟文字时不转换（如 `/赞说得好`），要先接一个标点。

**@** 的规则：

- 只接受纯数字 QQ 号，不能 @ 全体成员。
- 群聊里转换成 @；私聊里 @ 没有意义，标记会被直接去掉。

**分段**由模型自己决定：它在想分开发的地方写 `[分段]`，插件就在那里拆成几条依次发出。

- 每条带着自己那一段里的小黄脸和 @，天使之心加的引用跟着第一条。
- 后面每条发出前，按这条的长度停顿 0.6～3 秒，像在打字。
- 回复超过 300 字时不分段，`[分段]` 换成换行：长篇解释本来就不该拆，天使之心把 800 字以上的回复排成长图时，图里也不会出现标记。
- 不在 aiocqhttp 平台时，`[分段]` 也换成换行。

只处理模型生成的回复，插件指令的输出不受影响。没有配置项。要让模型用上 `/表情名`、`[@QQ号]`、`[分段]`，需要在人格提示词里写明用法。

## 安装

在 AstrBot WebUI「插件」页用仓库地址安装：

```text
https://github.com/happycola233/astrbot_plugin_qq_message_plus
```

或者把整个文件夹放到 AstrBot 的 `data/plugins/` 下，再重启 AstrBot。

装过旧版 `astrbot_plugin_qq_face_inline` 的话，先把旧版卸载，再装这个。

## 注意

不要同时开启 AstrBot 的「分段回复」：开启后每个消息段会单独发送，小黄脸和 @ 会和文字拆成几条消息。分段交给本插件的 `[分段]` 标记。

## 数据来源与许可证

表情名到 ID 的对照表 `qq_faces.py` 由 [Koishi QFace](https://github.com/koishijs/QFace) 的 [`_index.json`](https://koishi.js.org/QFace/assets/qq_emoji/_index.json) 生成，只收经典小黄脸和超级表情（骰子、接龙、Unicode emoji 需要特殊处理，没有收录）。QFace 使用 MIT 许可证，见 `LICENSE-QFace`。
